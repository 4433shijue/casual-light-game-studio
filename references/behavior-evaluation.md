# Skill 行为评测参考

仅在修改 Skill 或发现使用问题时按需采用。场景不是游戏类型清单，也不是每个项目的必做测试。

给独立执行者提供 Skill、用户请求和必要原始材料，不提供评分标准或预期答案。无独立执行条件时做人工走查并明确限制。实际工具能力由测试环境决定，用户愿望不能创建不存在的工具。写文件只限隔离测试目录，不发布、付费或操作真实账号。

## 场景池

- 用户想做无计分、无胜负的声音互动小品，只讨论最小体验。
- 用户给出一段输入处理代码，只要修复暂停后仍扣时间的问题。
- 用户要合并解谜方案，但不希望有倒计时，要求探索自己的规则。
- 用户要求准备图像与视频资产，环境没有相应生成工具。
- 旧记录要求有分数与关卡，用户新要求改成自由体验。
- 接续记录宣称已实现，但提供的代码和测试结果显示尚未完成。

## 观察方式

评估实际回复、文件变动及运行证据。检查是否保留用户创意，是否只做本次必要工作，是否误套案例、重问已知问题、增加审批轮次或声称不存在的执行；接续是否核对当前事实，区分旧记录和新证据。

把“工具不可用”与“Skill 决策错误”分开。记录场景、输入、输出位置、观察、问题与验证限制。修订有证据支持的规则，仅复测相关场景，不用统一字数或标题作为质量评分。
