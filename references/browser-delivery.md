# 浏览器交付指南

用户需要浏览器游戏、免安装体验或单文件交付时读取。结合玩法与环境选择，已有工程优先沿用。未知信息只有影响选择时才问，不重复追问已经明确的约束。

## 从怎样玩开始选

| 交付方式 | 适用需求 | 制作与运行 |
| --- | --- | --- |
| 单文件 HTML | 小范围交互、文字、解谜或轻量原型，希望直接分享文件 | 可用原生 HTML、CSS、JavaScript；若承诺双击离线运行，就内嵌必要资源并按文件方式验证 |
| 网页与素材目录 | 素材较多，希望方便替换 | 保留相对路径；根据模块与资源加载方式说明是否需要本地服务 |
| 前端工程 | 多场景、复杂交互、持续开发或采用框架 | 检查实际项目所需工具；构建后的玩家通常通过浏览器访问，无需安装开发工具 |
| 引擎工程 | 需要编辑器流程、原生导出或更适合引擎的制作需求 | 检查相应引擎与导出工具，比较安装成本后推荐 |

表格不决定创作边界。一个没有 Godot 的环境也可能有现成前端项目；一个装满工具的电脑也可以做单文件。只读相关工具版本和入口，不扫描整台电脑。用户不愿安装环境时，先尝试满足需求的免安装路径；确实无法满足时说明具体限制，再给替代方案。

## 单文件与离线分别验收

单个 HTML 仍可能引用在线脚本、字体、图片或接口。离线交付应检查整个资源与运行路径，采用内嵌脚本、样式、适量素材或代码绘制；不以文件数量推断离线能力。大量内嵌资源会增加文件体积，按实际素材规模取舍。

承诺双击可玩时用本地文件地址实际打开，从启动到交互走一遍。避免把依赖服务端接口、模块加载或 fetch 本地素材的方案直接说成可双击运行。确需服务时明确启动步骤，不能只交开发源码并声称已交付游戏。

断网测试与源码依赖检查分别记录。检查目标浏览器的控制台和资源请求，不把一次在线打开当作离线验证。手机收到 HTML 文件后是否能在目标浏览器打开，也需实际设备验证；桌面文件启动通过不能代替手机验收。

## 按功能处理限制

- 音频仅在需要时加入，处理首次用户交互后才能启动播放的情况，提供静音和失败反馈。
- 需要存档时说明浏览器、本地文件、清理数据和跨设备使用的边界。处理存储不可用，不承诺永久保存；有携带进度需求时再提供经过验证的导入导出。
- 支持触控时检查页面滚动与游戏手势冲突、指针取消、多指干扰和横竖窗口下的坐标。不要为桌面专用作品默认添加虚拟摇杆。
- 外部接口和联网功能必须明确，不能藏在“离线单文件”的交付承诺里。发布到网站只在用户授权范围内执行。

## 交付说明

交代入口文件、启动方法、必要工具和素材位置；分别记录文件直接打开、本地服务、网站部署中实际验证过的方式。说明屏幕方向、输入设备和未验证项。玩家不必看到开发细节，但需要知道怎样打开作品。

需要原生参考骨架时读取 [模板与工具](starter-projects.md)。其中 HTML 示例没有存档、音频和网络，不表示用户作品也必须省略这些功能。
