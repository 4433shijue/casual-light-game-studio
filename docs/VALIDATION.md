| 实际请求 | 输出观察 |
| --- | --- |
| 幽灵邮局整套称呼与首轮教学 | 给出夜班邮差、投递委托和路线菜单；明确交互假设，示例人物与地址标为虚构，没有新增体力或战斗 |

这些是文本任务试用，没有真实游戏界面可供检查，尚不能证明实际字体、换行与布局适配。本次未改游戏骨架，也未重新执行下方的历史引擎测试。附带 Python 工具的文档示例命令重新执行通过。

发布包制作时核对源目录、本地安装副本与 ZIP 的逐文件内容。GitHub 同步后另核对提交树、版本标签和下载附件，发布结果由交付记录说明。

## 历史验证

下面记录实际做过的检查，时间为 2026 年 9 月 14 日。仓库发布时另检查文档链接与示例命令。后续修改需要根据影响重新验证。

## 工具与模板

四个 Python 工具经过正常输入、错误字段类型、重复 ID、依赖循环、任务排序、防覆盖和复制一致性检查。

Phaser 在 Node 24 下通过核心玩法测试，并在浏览器观察过点击计分、目标变化、超时失败、重玩与成功结算。Godot 4.6.3 完成无界面场景启动和玩法测试，包含暂停、成功、失败、结束后输入和多次重置。

Godot 尚未完成可视化人工试玩，各平台导出也没有全部验收。自动测试能证明部分行为正确，无法替玩家决定好不好玩。

## Skill 行为试用

三个未继承开发讨论历史的独立执行者处理了四个具体请求。没有给它们评分标准或预期答案，随后检查实际回复与产物。

| 请求 | 观察 |
| --- | --- |
| 只修暂停扣时间 | 只增加暂停判断，没有重新策划；另用 Node 检查扣时、暂停和恢复 |
| 无计分风铃小品 | 保留声音与自由体验，没有强加关卡或结算 |
| 故事关联的合并解谜 | 保留自定义规则，并在缺少生成工具时给出外部交接建议 |
| 旧记录与代码冲突，用户又改方向 | 更新决定，纠正完成状态，明确历史日志与本次未执行的区别 |

两个创意请求由同一执行者分别回答，其余请求独立执行。这些场景提供了有限证据，不能推断所有模型都能同样处理。
