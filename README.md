# 小游戏开工啦 · Casual Light Game Studio

让一个小游戏点子，慢慢长成能玩的东西。

你带来创意，AI 帮你整理玩法、选择技术、准备资产，再按需要推进实现和试玩。可以先做一个能点起来的小原型，也可以认真养成一部小作品。第一天暂时不用把续作都规划好。

这是给支持 Skill 或读取项目指令的 AI 智能体使用的制作资料包。里面有主指令、案例、提示词、项目模板和 Python 工具。使用它需要你自己的 AI 工具；生图、生视频等能力取决于那个工具实际支持什么。

当前版本 **v1.2.1 · 数值推演与作品交付**。可在 [版本发布页](https://github.com/4433shijue/casual-light-game-studio/releases/tag/v1.2.1) 下载完整 Skill ZIP，更新内容见 [更新记录](CHANGELOG.md)。

## 先试这一句

安装后，把你的想法接在这段话后面。

```text
使用 $casual-light-game-studio。
我想做一个没有分数、没有失败的风铃小游戏。
鼠标像风一样拨动风铃，先帮我想一个最小体验，暂时不写代码。
```

如果你的智能体不支持 `$技能名`，请让它读取这个仓库里的 `SKILL.md`，再提出需求。能读取指令不代表它同时具备运行游戏、生成图片或操作文件的能力，这几项要分别看。

## 它能陪你做什么

| 你现在的状态 | 可以交给它的工作 |
| --- | --- |
| 有点子，还没想清楚 | 找到体验重点，讨论玩法和最小验证范围 |
| 准备动手 | 推荐适合的平台与框架，拆出实现步骤 |
| 缺图、缺声音 | 整理资产规格和提示词；能力具备时继续制作与检查 |
| 游戏缺少自己的说法 | 设计世界观称呼、界面提示和角色口吻，或只改几句文案 |
| 已经有游戏 | 局部修复、加内容，检查相关回归 |
| 上次做到一半 | 读取项目接续记录，核对代码与证据后继续 |

默认先出方案，从概念验证版起步。你说“直接做”，它就应在授权范围内推进；你说“只看看”，它就先分析。一个暂停按钮坏了，也用不着重新写一部游戏开发史。

## 创意归你，参考随便用

案例、模板和脚本都可以改、可以组合，也可以跳过。没有计分的游戏、没有关卡的体验、库里没出现过的古怪点子，都可以继续讨论。

Godot 和 Phaser 附带的点击游戏用于演示输入、计时、暂停、结算与重玩。你的作品不必点圆圈。圆圈对此没有意见。

## 也能给游戏想一套自己的说法

同样是任务列表，幽灵邮局里可以叫“待投信件”，阳台茶摊里可以叫“今日茶单”。名称跟着设定和功能走，按钮该干什么也要让人看懂。“退出”暂时不用改成“辞别人间”，玩家可能只是想去拿杯水。

你可以让它设计整套文案，也可以只改角色称呼、检查已有术语有没有打架。参考 [文案设计手册](references/game-copywriting.md) 中的三个虚构案例，或者直接说出你的设定。安装包不要求额外安装写作 Skill。

## 安装与阅读顺序

先看 [安装说明](docs/INSTALL.md)，装好后按 [用户指南](docs/USER_GUIDE.md) 开始。想直接复制需求，可以翻 [使用示例](docs/EXAMPLES.md)。遇到识别、脚本或素材问题，查看 [常见问题](docs/FAQ.md)。

这个仓库根目录就是技能目录。下载时请保留完整文件夹，只有 `SKILL.md` 会缺少它引用的案例与模板。

## 包里有什么

| 位置 | 内容 |
| --- | --- |
| `SKILL.md` | 智能体的主指令与按需读取入口 |
| `references/` | 案例、框架建议、资产提示词、接续与验证参考 |
| `assets/templates/` | 项目简报、术语与文案、试玩和接续记录模板 |
| `assets/starters/` | 原生单文件 HTML、Godot 4 与 Phaser 3 的参考骨架 |
| `scripts/` | 创建工程、生成文档、生成及检查资产清单 |

阅读资料不需要先装 Python。运行附带脚本需要 Python 3.10 或更高版本；跑游戏模板还需要对应引擎或浏览器开发环境。具体命令见 [工具与模板说明](references/starter-projects.md)。

## 当前验证到哪里

已有 Python 工具测试、Phaser 浏览器试玩、Godot 无界面启动与玩法测试，也做过局部修复和创意场景的独立模型试用。各平台导出、所有模型兼容性和游戏是否好玩，都不能由这些测试一并盖章。

详细范围见 [验证记录](docs/VALIDATION.md)。发现问题欢迎带上复现步骤提 Issue，尤其欢迎告诉我们“这里把我的点子带跑偏了”。这种反馈比多堆十张模板有用。

本仓库暂未指定开源许可证。Phaser、Godot 及外部生成素材各自的许可条件需分别确认。

## 没装引擎，也能开工

如果你只想把小游戏发给朋友，原生 HTML 可能就够用。包里附了 [风与色单文件示例](assets/starters/html/index.html)，设计为保存完整文件后在桌面浏览器直接打开。它没有在线库或外部素材；本次已验证服务方式运行，本地文件与断网测试受工具限制尚未完成，详见验证记录。也可以根据作品需要选择素材目录、前端工程或游戏引擎。

横屏、竖屏和窗口适配按玩法选择。桌面调饮料可以直接拖动器具，路线游戏可以让地图占满主要空间。示例的侧栏不用跟着你去下一款游戏上班。

更多取舍见 [浏览器交付指南](references/browser-delivery.md) 和 [方向与布局说明](references/layout-and-input.md)。手机能否直接打开收到的文件，仍需在对应设备上检查。

## 操作顺不顺，试玩后再细调

可以只让它分析拖动吸附，也可以带着试玩记录找问题。新增 [手感反馈](references/feel-and-feedback.md) 与 [试玩诊断](references/playtest-diagnosis.md) 两个入口，按当前任务取用。

一个物品放不进去，先看看落点和规则，再决定改哪里。暂时不用给收纳盒加抽卡系统。方案和试玩表也允许自由探索、一次性叙事与无胜负体验。

## 模型差异与接续

不同模型对指令的理解、语言风格、创意表达和工具支持存在差异，同一模型多次生成也可能不同。创意和措辞允许变化，但用户要求、已确认的世界观、术语及真实机制仍应保持一致。能力不足或信息缺失时应说明限制，不把推测当作事实。

换模型时带上已有设定、术语表、采用稿和满意样句，注明必须保留与可自由发挥的部分。样稿提供风格参考，不自动变成剧情事实。测试只代表记录的环境与场景，不保证所有模型达到同样效果。

## 独立游戏文案工作室

只想写文案，可以安装 [独立版](standalone/game-copywriting-studio/README.md)，使用 `$game-copywriting-studio`。完整工作室仍保留全部文案能力，不要求额外安装。两个发布包共用当前发布版本号，独立版首次发布于 v1.2.0。

## 算一算，也交到别人手上

实际有资源或成长规则时，可以用 [数值推演](references/balance-and-rules.md) 检查是否存在赚不到下一份原料、解锁条件互相等待等问题。计算需要写清假设，模拟通过不代表玩家一定觉得好玩。

准备分享时，[展示与交付](references/showcase-and-delivery.md) 帮你整理玩法介绍、操作说明、代表性画面和启动步骤。没录过的视频就写待录制，计划支持手机就先留在计划里，宣传稿不用替程序提前毕业。
