# 从一句需求开始

给出当前任务、必要设定和实际规则即可。有原稿就贴原稿，需要工程接入时再提供格式。没有角色的游戏不用先领养一个角色。

## 角色与情境

对白可以说明人物与谁说话、想达到什么目的、知道哪些事实。口吻按游戏选择，不默认幽默。首次提示可解释原因，重复提示可以简短，但消耗数量与不可逆后果不能省掉。

只要文字时会交付候选稿。触发次数、冷却或分支条件若尚未实现，应作为建议或待实现项，不能把写好的台词当成已经接入游戏。

## 换模型继续写

不同模型、上下文与工具能力会影响输出，同一模型多次生成也可能不同。创意与措辞允许变化，用户要求、已定世界观、术语和真实机制保持一致，缺少信息时说明限制。

```text
使用 $game-copywriting-studio。
请先读取我提供的设定、术语表和采用稿。
角色称呼与机制数值必须保留，样稿只供语气参考，不作为新增剧情。
本次只改台词措辞，可以自由调整句式，不改人物关系。
```

需要记录时沿用项目文档，或使用 [可选术语表](assets/templates/game-lexicon.md)。只有单句任务时直接交句子。没有界面测试就不能说字体和换行已经正常。

本包测试不代表所有模型表现一致，也不代表真实玩家对文案满意。完整验证范围见 [验证说明](VALIDATION.md)。
