# 文案分支验证

2026 年 9 月 21 日，分别通过小游戏工作室和独立文案工作室两个入口进行试用，每个入口由一名独立执行者处理同一组六个请求。比较遵守约束和范围，不要求文字相同，也没有将它当作不同模型之间的评测。

| 请求 | 两个入口的实际表现 |
| --- | --- |
| 只改一句缺料提示 | 均只给出“茶叶不足”，没有展开策划 |
| 邮差面对熟人与陌生人 | 关系改变称呼和表达，均未编造修复日期 |
| 首次与重复缺料提示 | 保留 {missing}，并注明切换机制尚未实现 |
| JSON 机制说明 | 保留 brew_help、{count}、消耗3片茶叶与恢复体力效果 |
| 换模型接续术语 | 经验继续叫阅历，保留 {amount}，没有把幽默样句变成新剧情 |
| 无剧情色带 | 只交付拖动提示与退出按钮，没有新增人物或故事 |

独立执行者仅读取独立包内入口与参考完成任务，没有依赖主工作室外部资料。两个入口的称呼与机制保持一致，部分措辞不同。

两个 Skill 格式检查通过。打包测试覆盖共享资料漂移检测与修复、包内链接、重复构建得到相同 ZIP、已有输出目录防覆盖，以及拒绝在源目录内生成附件。独立包不含游戏骨架或运行脚本，用户不需要额外写作 Skill。

共享资料由主包维护，独立副本含来源注释。安装、指南和新参考经过写作检查；句长提醒按教程和表格用途人工复核。

这次只验证文本任务、资料和打包过程，没有真实玩家评价、游戏界面或触发运行时测试。不保证所有模型相同效果，也未验证所有智能体的技能自动发现。游戏骨架没有改动，历史本地文件打开、断网和真机未验证项仍保留。
